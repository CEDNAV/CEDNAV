Protocolos de Comunicación y Puertos RF1-RF8
TCP · Puerto 6001

Canal de Mando Crítico — IC Gateway

Enlace persistente bidireccional con el Gabinete de Interfaz. TX: tramas binarias de 29 bytes con checksum XOR. RX: telemetría de 31/33 bytes. Heartbeat cada 100 ms. Watchdog 1200 ms.

UDP · Puerto 4531

Joystick Táctico

Recepción de frames binarios $BPJ con ejes X/Y/Z (signed int8) y 12 botones. Deadzone ±5 aplicada en backend para filtrar ruido mecánico.

UDP · Puerto 5501

Teclado Naval / Panel Táctil

Comandos ASCII desde el panel de 36 teclas y feedback visual hacia LEDs físicos del hardware vía FeedbackService. Bidireccional.

UDP · Puerto 8000

CMS — Sistema Gestión Combate

Recepción de tramas de 42 bytes con datos de pistas tácticas (blancos). CMSService decodifica y actualiza el store reactivo del Radar PPI en tiempo real.

UDP · Puertos 70xx

Sensores NMEA 0183

GPS ($GPGGA), Girocompás ($HEHDT), Inclinómetro Pitch/Roll. Usados para estabilizar el horizonte táctico del Radar PPI y calcular rumbo real del buque.

UDP · 37511 / 37512 / 37513

Video EOT H.264 — por Estación

Flujo H.264 segregado: Estribor :37511 · Babor :37512 · Popa :37513. FFmpeg (unpacked ASAR) decodifica y transmite al frontend.

WebSocket · Puerto 8001

Bus Interno Backend → Frontend

Canal Full-Duplex JSON entre Node.js y Svelte. Distribuye estados IC, telemetría, pistas CMS y comandos del operador sin bloquear el Event Loop.

Patrones de Diseño Aplicados 2 / 6.2

Observer / EDA

Arquitectura Orientada a Eventos mediante EventEmitter. El servidor reacciona asincrónicamente a la llegada de datos sin bloquear el hilo principal.

State — FSM

BinaryProtocolService actúa como Máquina de Estados Finita. Mantiene la "verdad única" de la consola y gestiona transiciones RWS → EOT → CMS.

Bridge (Puente)

Separa la abstracción lógica de la consola de su implementación física. Permite reemplazar hardware periférico sin alterar la lógica central de procesamiento.

Singleton

StationManager y SensorsService poseen instancia global única. Garantiza exclusividad en el acceso a sockets de red y evita colisiones de recursos.

Layered Architecture

5 capas desacopladas: Infraestructura → Dominio → Aplicación → Presentación. Cada capa evoluciona de forma independiente sin afectar las demás.

Reactive Stores

Svelte Stores como fuente de verdad reactiva en el frontend. Actualizados vía WebSocket, garantizan refresco selectivo y eficiente del HMI.
