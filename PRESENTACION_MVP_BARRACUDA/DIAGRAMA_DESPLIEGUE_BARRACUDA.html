2. Nodos Físicos del Despliegue — Detalle por Zona § Physical Nodes
ZONA A — PC CONSOLAS NAVALES (×3)
HARDWARE

🖥️ PC Industrial C1 / C2 / C3

Tipo: PC industrial COTS (Commercial Off-The-Shelf)
S.O.: Linux Ubuntu LTS 22.04+
NIC 1: 192.168.xx.xxx — Control y telemetría
NIC 2: 192.168.xx.xx — Video EOT segregado
Ubicación: Puesto de combate del buque (Estribor / Babor / Popa)
Arranque: Systemd → barracuda.service (RestartPolicy=always)

PROCESO: ELECTRON MAIN

⚙️ Electron v30 — Main Process

Ejecutable: barracuda-svelt (paquete .deb)
Rol: Orquestador del ciclo de vida, lanza backend Node.js como proceso hijo y configura la ventana Chromium del frontend.
IPC: ipcMain ↔ ipcRenderer para comunicación Main/Renderer
ASAR: asarUnpack para FFmpeg binario

PROCESO: BACKEND NODE.JS

⚙️ server.js — Event Loop EDA

Runtime: Node.js v20+ (V8 Engine)
Puertos escucha: TCP 6001 (IC), UDP 4531/5501/8000/70xx, WS 8001
Heartbeat: setInterval 100ms con drift compensation
Servicios: BinaryProtocolService, TCPService, SensorsService, StationManager, FeedbackService, CMSService, NMEAService
PID: Proceso hijo de Electron Main

PROCESO: FRONTEND SVELTE

🎨 Chromium Renderer — HMI

Framework: Svelte 4 compilado por Vite 5
Conexión: WebSocket ws://localhost:8001
Componentes: Radar PPI (SVG), Gauges, Video EOT, Hacking View, Settings Panel
Estado: Svelte Stores reactivos (telemetría, gyro, pistas CMS)
Renderizado: Chromium sandboxed dentro de Electron

PROCESO: FFMPEG

🎬 FFmpeg — Decodificador H.264

Binario: ffmpeg-static (asar.unpacked)
Lanzamiento: child_process.spawn() desde backend
Puerto entrada: UDP 37511 (C1) / 37512 (C2) / 37513 (C3)
Salida: Frames decodificados → pipe IPC al Renderer
Aislamiento: Proceso independiente del Event Loop

ZONA B — GABINETE DE INTERFAZ (IC)
NODO: IC CONTROLLER

🔋 Gabinete de Interfaz — FFS-RWS Core

IP: 192.168.xx.xxx
Puerto: TCP 6001 (server socket, espera conexión)
Protocolo: Binario propietario ICD
RX desde BARRACUDA: Tramas TX de 29 bytes con XOR checksum
TX hacia BARRACUDA: Respuestas RX de 31/33 bytes con telemetría
Función: Traduce comandos de software a señales de control del hardware de armas (servomotores, relés, sensores de posición)

HARDWARE CONTROLADO

⚔️ Hardware del Sistema de Armas

Servomotores: Control de ronza (bearing) y elevación
Sistema EOT: Cámaras ópticas con tracking
Sensores: Encoders de posición angular
Seguridad: Relés de habilitación de disparo (gated por CMS)

ZONA C — PERIFÉRICOS DE ENTRADA
UDP :4531

🕹️ Joystick Táctico

3 ejes: X (ronza), Y (elevación), Z (zoom)
12 botones: Funciones tácticas configurables
Formato frame: $BPJ + datos binarios (signed int8)
Frecuencia: ~100 Hz
Procesamiento: Deadzone ±5 aplicada en backend

UDP :5501 — BIDIRECCIONAL

⌨️ Teclado Naval / Panel Táctil

36 teclas: Funciones de mando tácticas
Entrada: Comandos ASCII (ENERGIZE_EOT, FIRE_ENABLE, etc.)
Salida: Feedback 5 bytes → LEDs físicos del panel
Lógica: LEDs SOLO se encienden cuando el IC confirma el estado

ZONA D — SENSORES DE NAVEGACIÓN (NMEA 0183)
UDP :70xx

📍 GPS — $GPGGA

Posición geográfica del buque (Lat/Lon). Usado para overlay en carta náutica del Radar PPI.

UDP :70xx

🧭 Girocompás — $HEHDT

Heading verdadero del buque. Controla la rotación del PPI en modo "Course Up" y compensa la orientación de las estaciones.

UDP :70xx

📐 Inclinómetro — Pitch/Roll

Datos de estabilidad del buque. Lectura en Big-Endian (corrección DEF-02). Usado para compensación de horizonte.

ZONA E — SISTEMAS EXTERNOS (CMS + VIDEO)
UDP :8000 — MULTICAST

⚔️ CMS — Sistema Gestión de Combate

Tramas: 42 bytes por pista táctica
Contenido: Blancos (targets), bearing, range, clasificación NATO
Frecuencia: ~5 Hz (actualización de pistas cada 200ms)
Función crítica: Habilitación de asignación de mando (cmsEnabled)

UDP :37511 / :37512 / :37513

📷 Cámaras EOT — H.264 Stream

Segregación: Un puerto por estación
C1 Estribor → :37511
C2 Babor → :37512
C3 Popa → :37513
Codec: H.264/AVC sobre UDP RTP
Decodificación: FFmpeg spawn en cada PC consola

6. Procesos en Ejecución por Nodo Consola § Runtime Processes

🖥️ PID 1 — Electron Main

Comando: /opt/barracuda-svelt/barracuda-svelt
Lanzado por: Systemd (barracuda.service)
Rol: Orquestador del ciclo de vida, crea la ventana Chromium y spawns los procesos hijos.
Restart: Automático ante fallo (RestartPolicy=always)

⚙️ PID 2 — Node.js Backend

Comando: node backend/src/server.js
Lanzado por: Electron Main (fork/spawn)
Puertos: TCP 6001, UDP 4531/5501/8000/70xx, WS 8001
Event Loop: Heartbeat 100ms + listeners UDP + TCP data handler

🎨 PID 3 — Chromium Renderer

Proceso: Chromium GPU + Renderer (sandboxed)
Lanzado por: Electron Main (BrowserWindow)
Contenido: Bundle Svelte compilado (index.html + app.js + app.css)
WebSocket: Cliente ws://localhost:8001

🎬 PID 4 — FFmpeg Decode

Comando: ffmpeg -i udp://@:3751X -f rawvideo ...
Lanzado por: Backend (child_process.spawn)
Puerto UDP: 37511 (C1) / 37512 (C2) / 37513 (C3)
Salida: Frames descomprimidos vía pipe stdout
